# Writing Craft

Write for the actual audience and task, not for an imagined generic product. Prefer concrete nouns, precise verbs, domain language, and sentence rhythm that fits the medium. Remove ceremonial headings, repeated conclusions, filler transitions, empty superlatives, generic transformation language, and marketing claims that could describe anything.

Never invent credibility. Metrics, testimonials, benchmarks, security claims, customer counts, compatibility and test outcomes must be supported or explicitly marked as placeholders/unknown.

For UX copy, name the action or consequence instead of defaulting to vague labels when a more exact label exists. For technical docs, make steps executable and completion criteria observable.

For code comments, keep information the code cannot state cleanly: intent, invariant, non-obvious tradeoff, external constraint, or hazardous edge case. Remove comments that merely narrate the next line.
