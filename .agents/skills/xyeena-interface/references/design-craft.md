# Xyeena interface craft reference

## 1. Read the product before styling
Identify the user, the job they are trying to complete, the content that is real, existing tokens/components, brand constraints and implementation stack. Preserve strong existing direction. If identity is materially absent, obtain a minimal direction rather than inventing a default "AI SaaS" aesthetic.

## 2. Shape the information
Make hierarchy visible through order, typography, density, grouping and contrast before reaching for decoration. Sections and components exist because content or interaction needs them, not because a landing-page template expects them.

## 3. Establish visual character
Choose a small number of strong decisions in typography, spacing, color, imagery, borders/material and motion. Consistency does not mean uniformity: vary rhythm according to content. Use cards when they represent real grouping, not as the universal container.

## 4. Typography
Use readable line length, deliberate hierarchy, stable text metrics, and type choices that match the product. Avoid forcing monospace as shorthand for "technical" or giant display type when the content cannot support it.

## 5. Color and themes
Choose theme from product context, not because dark mode looks futuristic. Use accent colors for semantic or hierarchical purpose. Maintain contrast and meaningful states across every shipped theme.

## 6. Interaction and motion
Interactive elements need visible affordance, focus, hover/pressed/disabled states where applicable, and real behavior. Motion explains change, continuity or hierarchy; it should not be a default entrance animation on every element. Respect reduced motion.

## 7. Responsive behavior
Design intermediate widths, not only phone and desktop endpoints. Verify reflow, navigation, tap targets, text wrapping, dense tables/forms, media and overflow. Preserve priority rather than merely stacking everything.

## 8. Human states
Check keyboard navigation, focus order, contrast, labels, error association, empty/loading/error/success states, long content and localization pressure where relevant.

## 9. Anti-generic diagnostics
Investigate rather than automatically ban: hero + fake metric blocks, identical feature-card grids, fashionable bento layouts, fake terminals, gradient text, glass everywhere, excessive rounding, decorative status dots, three-step boilerplate, logo bars with invented brands, highlighted middle pricing tiers, generic CTAs and copy that could name any product. Keep a pattern only when the real content and hierarchy justify it.

## 10. Delivery evidence
Render the actual app, exercise critical flows, inspect console/network, capture representative widths, and run project-native accessibility/performance tooling when available. A polished screenshot with broken behavior fails.
